# Production API

All API endpoints use `/v1`, JSON, bounded input validation and no-store responses. Session identity always comes from authentication, never user IDs in the request body. Browser cookies require exact-origin JSON mutations. Native clients use an opaque Bearer token. Only approved Rutgers domains are accepted; the server sets the school implicitly.

| Method/path                      | Authentication                | Behavior                                                                                                                                                                               |
| -------------------------------- | ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET /healthz                     | Public                        | DB liveness.                                                                                                                                                                           |
| GET /readyz                      | Public                        | Runtime health and offsite-backup last success; no credentials.                                                                                                                        |
| GET /privacy, /terms             | Public                        | Operator policy pages.                                                                                                                                                                 |
| GET /v1/config                   | Public                        | School domains, support contact and public tile configuration.                                                                                                                         |
| POST /v1/auth/request-code       | Public/rate-limited           | `{email}`. Delivers a one-time code through configured SMTP. No code response.                                                                                                         |
| POST /v1/auth/verify             | Public/rate-limited           | `{email,code,termsAccepted:true}`. Verifies code and creates/resumes an account. Sets a browser session cookie. Only a native client header returns a token.                           |
| POST /v1/auth/logout             | Session                       | Revokes current session.                                                                                                                                                               |
| POST /v1/auth/logout-all         | Session                       | Revokes every session for the signed-in account.                                                                                                                                       |
| GET /v1/bootstrap                | Session                       | Own state, admin flag, up to 500 eligible peers/relationship profiles, server-gated approximate presence and expiry. No peer emails or raw GPS. No bulk message history.               |
| PUT /v1/profile                  | Session                       | Validated profile; first save completes onboarding.                                                                                                                                    |
| PUT /v1/visibility               | Onboarded                     | `{audience,minutes,position?}`. Sharing requires an on-campus position; it is immediately quantized. Nobody clears it.                                                                 |
| PUT /v1/presence                 | Onboarded                     | `{position}`. Refreshes only already-enabled, unexpired sharing; cannot extend consent.                                                                                                |
| POST /v1/connections/:id         | Onboarded                     | `{action:request                                                                                                                                                                       | accept                                                                                    | remove}`. Only the recipient accepts. |
| POST /v1/blocks/:id              | Onboarded                     | `{blocked:boolean}`. Bidirectional enforcement and relationship/invite cleanup.                                                                                                        |
| GET /v1/messages/:id?cursor=UUID | Connected                     | Up to 100 messages plus `nextCursor`. Cursor must belong to this conversation.                                                                                                         |
| POST /v1/messages/:id            | Connected                     | `{text,clientId:UUID}`. Idempotent per sender/recipient; blocked/suspended peers denied.                                                                                               |
| GET /v1/events                   | Onboarded                     | Up to 200 upcoming visible events and own RSVP map. No private-event metadata to non-invitees.                                                                                         |
| POST /v1/events                  | Onboarded/rate-limited        | Title, campus, venue, startsAt/endsAt epoch ms, kind, category, description and invitee UUIDs. Invitees must be accepted connections. Future dates within 90 days, duration up to 24h. |
| PUT /v1/events/:id/rsvp          | Authorized attendee           | `{status:going                                                                                                                                                                         | declined                                                                                  | null}`. Null undoes response.         |
| DELETE /v1/events/:id            | Host                          | Cancels the event and revokes attendee access.                                                                                                                                         |
| POST /v1/reports                 | Onboarded/rate-limited        | Exactly one personId/eventId, reason/details. Saved to private queue; generic moderator notification.                                                                                  |
| GET /v1/account/export           | Session                       | Own account data only; no other accounts' private identity.                                                                                                                            |
| DELETE /v1/account               | Session                       | `{confirmation:DELETE}`. Removes live personal account data and revokes sessions.                                                                                                      |
| GET /v1/admin/reports            | Configured verified moderator | Open reports and limited subject/event context.                                                                                                                                        |
| POST /v1/admin/reports/:id       | Moderator                     | `{status:reviewed                                                                                                                                                                      | dismissed}`. Audited.                                                                     |
| POST /v1/admin/users/:id         | Moderator                     | `{status:active                                                                                                                                                                        | suspended}`. Suspensions revoke sessions/presence/events. Audited; own suspension denied. |
| POST /v1/admin/events/:id        | Moderator                     | Cancels reported event. Audited.                                                                                                                                                       |

Production has no `/api/demo/login` route. Default errors are JSON with a request ID, and unexpected failures omit stack traces and secret/internal details. Every read/mutation rechecks account and relationship access; clients poll rather than maintaining a privileged local copy as the authority.
